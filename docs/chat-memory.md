# Память и восстановление ответа

Обычный чат сохраняет пользовательское сообщение до вызова модели. Статус
сообщения — `pending`, `failed` или `done`. Если сервер или провайдер прервал
ответ, последний незавершённый ход можно повторить через кнопку в истории
или `POST /api/chat/sessions/{id}/messages/{message_id}/retry`.

Повтор доступен только для последнего незавершённого пользовательского сообщения.
Новый вопрос, slash-команда и создание задачи в этом чате ждут его завершения.
Нажатие на уже завершённый ответ или на сообщение другого чата возвращает 409.
Очередь в браузере ждёт повтора; переключение чатов не отправляет её в другой чат.
После перезагрузки браузера очередь не восстанавливается, но незавершённый ход
остаётся в SQLite.

Перед генерацией отдельный JSON-вызов разбирает явно заданные изменения рабочей
памяти. Он видит до четырёх последних пар сообщений и ограниченный снимок памяти.
Разбор сохраняется в `chat_messages.memory_update` и повторно не запускается
при восстановлении этого хода. При некорректном JSON допускается одна повторная
попытка с сообщением об ошибке валидации. Новое ограничение получает стабильный ключ;
исправление с тем же ключом заменяет прежнее значение и его источник.

Новая цель автоматически получает отдельный чат с собственной рабочей памятью
и общей долговременной памятью. Исходный чат сохраняет историю, цель, ограничения
и прогресс задачи. Первая цель в чате и повтор той же цели не создают ветку.
Неясное изменение вызывает уточнение. Цель хранится отдельно от ограниченного
окна сообщений и сохраняется в снимке при ограничении числа записей.

Обычный ввод, /goal и ручная запись цели через API используют общее правило
маршрутизации. Явное создание задачи с другой целью также создаёт ветку.
parent_session_id позволяет открыть исходный чат. Устойчивый operation_id
связывает запрос с уже созданным чатом и сообщением; потерянный HTTP-ответ можно
восстановить через GET /api/chat/sessions/{id}/operations/{operation_id}.
Повтор после ошибки или перезапуска использует сохранённый разбор и выбранную
модель. Команда /goal сохраняется с подтверждением без вызова модели.

Агент получает предварительный снимок памяти. Рабочая память и готовый ответ
сохраняются одной транзакцией в общей SQLite-базе; ошибка генерации, отказ
инвариантов или ошибка записи не оставляют частично применённых изменений.
Извлечение долговременных фактов выполняется после ответа и допускает отказ
без потери ответа. Ошибка интерпретатора рабочей памяти также не мешает ответу:
для этого хода фиксируется пустое изменение.
Если пользователь изменил рабочую память во время генерации, ответ не сохраняется:
нужно повторить его с актуальным снимком памяти.

Записи памяти содержат `source_session_id` и `source_message_id`. Интерфейс
открывает нужный чат и прокручивает историю к исходному сообщению. Для старых
записей и записей, созданных напрямую через API без источника, ссылка отсутствует.

Блокировка действий одной сессии работает внутри процесса. SQLite защищает
начало и завершение хода между процессами, но одновременный retry из разных
workers может вызвать модель несколько раз. Для локального запуска используйте
один Uvicorn worker. Для задачи изменения памяти действуют со следующего действия. Уже начатое
действие завершается по своему снимку; версии задачи проверяются отдельно.
В состоянии задачи действуют правила
[контролируемых переходов](controlled-transitions.md).

Контрактные проверки в `tests/test_chat_recovery.py` покрывают восстановление
после перезапуска, однократный разбор памяти, исправления, отмену, смену цели,
изоляцию чатов, ограниченное окно истории и атомарный откат записи.
