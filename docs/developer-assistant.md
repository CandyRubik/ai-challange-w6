# Ассистент разработчика: /help

Команда /help в основном чате отвечает на вопросы по README.md и docs/.
Без аргумента она объясняет структуру проекта. Например:

```text
/help
/help Где хранятся чат-сессии и память?
/help Как запустить приложение локально?
/help Какая сейчас ветка?
```

## Путь запроса

ChatSessionService распознаёт команду на backend. ProjectHelpService получает
свежий git-контекст через MCP stdio, ищет документацию через E5, FAISS и reranker,
передаёт доказательства выбранной модели и проверяет её цитаты.

MCP-клиент запускает python -m app.project_help.mcp_server, устанавливает сессию
и вызывает инструмент git_branch. Сервер читает только ветку и HEAD настроенного
PROJECT_ROOT. Результат содержит имя репозитория, branch, commit, detached и время
наблюдения. Detached HEAD отображается явно. Если Git, checkout или MCP недоступен,
ветка помечается как недоступная; ответ по документации по-прежнему возможен.

Модель получает документацию и результат инструмента как данные. Оркестратор
вызывает MCP; провайдеру не требуется function calling или доступ к файловой системе.
Ответ на точный вопрос о текущей ветке формируется из MCP без генерации и RAG.

## История, память и задачи

Ответ, источники, цитаты, версия индекса, модель и git-контекст сохраняются в SQLite.
Карточка «Контекст проекта» показывает реальный результат MCP и время его получения.
При повторе незавершённого /help сохраняется исходная модель, а git-контекст
запрашивается заново. Успешные ответы остаются историческими снимками.

/help не записывает рабочую или долговременную память,
не изменяет прогресс задачи. Команда доступна и при активной задаче. К запросу и ответу
применяются продуктовые инварианты.

## Локальный запуск и Docker

Подготовьте зависимости и модели по README. PROJECT_ROOT по умолчанию указывает
на корень этого проекта. Индекс автоматически строится при первом вопросе;
для подготовки демонстрации используйте python scripts/build_project_index.py.

В Compose checkout примонтирован read-only как /project. README и docs включены
также в Docker-образ. MCP показывает ветку этого checkout, а не компьютера
пользователя браузера. Текущий rsync-деплой доставляет документацию без .git,
поэтому на VDS git-контекст будет недоступен, пока в PROJECT_ROOT не размещён
настоящий checkout. Индекс хранится в writable-томе /app/data/project_index.

## Демонстрация

1. Открыть основной чат и отправить /help.
2. Спросить о хранении памяти и открыть ссылку на документацию.
3. Отправить /help Какая сейчас ветка? и раскрыть «Контекст проекта».
4. В другом checkout или после ручной смены ветки повторить вопрос: MCP покажет новую ветку.
5. Спросить о неописанной интеграции, которой нет в документации: ассистент сообщает
   об отсутствии подтверждённых сведений.

Сквозной прогон: python scripts/smoke_project_help.py --base-url http://127.0.0.1:8000.

## Видео

Демонстрационный MP4 — монтаж реальных кадров браузера, а не измерение скорости
генерации. Кадры сохраняются в data/day31-video/, результат —
data/day31-developer-assistant.mp4. Для сборки нужны ffmpeg и зависимости:

```bash
pip install -r requirements-demo.txt
python scripts/build_day31_video.py
```

На других системах задайте --font с путём к TTF-шрифту с поддержкой кириллицы.
Скрипт ожидает кадры интерфейса, перечисленные в SCENES; он не подменяет ответы
модели и не генерирует вымышленные результаты.
